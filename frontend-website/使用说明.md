# H.O 和悦酒店 · 官网 + 管理后台

模仿 YANG（杨邦胜设计集团）官网风格制作的高端酒店官网 + 全套管理后台，已对接 `D:\project\hotel` 的 Spring Boot 后端全部接口（前台用户接口 + 后台管理接口）。

## 启动方式

1. 确认后端已启动：`http://localhost:8080/ho-api/hotel` 能返回 JSON。

   **后端启动（重要 · Java 版本兼容）**：项目是 Spring Boot 2.0.5，本机 JDK 是 21，直接用 IDE 或普通命令启动会报 `InaccessibleObjectException: module java.base does not "opens java.lang"`（CGLIB 老版本不兼容 Java 16+ 的模块封装）。正确做法二选一：
   - **双击 `D:\project\hotel\启动后端.bat`**（已内置兼容参数，推荐）；
   - 或命令行：
     ```bash
     cd /d D:\project\hotel
     set MAVEN_OPTS=--add-opens java.base/java.lang=ALL-UNNAMED --add-opens java.base/java.util=ALL-UNNAMED --add-opens java.base/java.lang.reflect=ALL-UNNAMED
     mvn spring-boot:run
     ```
   - 若用 IDEA 启动：Run Configuration → VM options 里加上上面那串 `--add-opens` 参数；或把 Project SDK 换成 JDK 8（系统里 `D:\java1.8` 只有 Linux 包，Windows 用不了，需另装 Windows 版 JDK 8）。

2. 在本目录运行静态服务器（不要直接双击 HTML，跨域会导致接口失败）：

```bash
cd hotel-web
python -m http.server 8899
```

3. 浏览器打开：

| 页面 | 地址 | 说明 |
|---|---|---|
| 酒店官网（前台） | `http://localhost:8899/index.html` | 客人浏览、预订 |
| 管理后台 | `http://localhost:8899/admin/index.html` | 员工管理 |

> 用 `localhost` 或 `127.0.0.1` 都可以，前端 API 会自动跟随当前页面域名，保证登录 Cookie 同源。

## 前台接口（index.html）

| 功能 | 页面位置 | 后端接口 |
|---|---|---|
| 酒店信息（页脚电话/地址/邮箱） | 页面加载 | `GET /hotel` |
| 房型列表（7 种房型卡片） | 客房展示区 | `GET /hotel/room` |
| 房型详情 | 客房卡片「详情」 | `GET /hotel/room/{id}` |
| 查询空房 | 顶部预订查询条 | `GET /hotel/room/rest` |
| 登录 / 注册 | 登录/注册弹窗 | `POST /login/user`、`POST /register/user` |
| 员工登录进入后台 | 导航栏「员工登录」按钮 / 登录弹窗底部入口 → 官网内员工登录弹窗 | `POST /login/admin` |
| 个人资料 / 修改资料 / 改密 / 退出 | 个人中心弹窗 | `GET /user/profile`、`POST /user/update`、`POST /user/updatePassword`、`POST /user/logout` |
| 提交预订 | 预订弹窗 | `GET /user/order/add` |
| 我的订单 | 我的订单弹窗 | `GET /user/order` |
| 订单详情 / 删除 / 取消 / 支付 | 订单列表操作 | `GET /user/order/{id}`、`GET /user/order/delete`、`GET /user/order/cancel`、`POST /user/order/pay` |

## 后台接口（admin/index.html）

共 9 个模块，覆盖全部 `/op/**` 与 `/admin/**` 接口：

| 模块 | 功能 | 主要接口 |
|---|---|---|
| 控制面板 | 订单数/客户数/客房数/房型数统计、最近订单 | `/op/order/count`、`/op/user/count`、`/op/order` |
| 订单管理 | 列表、按姓名手机查、按客户查、增删改、支付、取消、超时 | `/op/order/**` |
| 入住管理 | 入住记录、办理入住、退房、换房、删除 | `/op/check-in/**` |
| 客房管理 | 列表、按状态/房型筛选、增删改 | `/op/room/**` |
| 房型管理 | 列表、只看有空房、增删改 | `/op/room-type/**` |
| 预订方式 | 列表、增删改 | `/op/order-type/**` |
| 客户管理 | 列表、按用户名查、增删改、改密码 | `/op/user/**` |
| 员工管理（管理员） | 列表、增删改 | `/admin/operator/**` |
| 酒店设置（管理员） | 修改酒店名称/电话/邮箱/地址/网址，保存后前台同步 | `GET /op/hotel/update`、`GET /hotel` |

## 已知后端注意点

- `UserController.getProfile` 原第 84 行对空身份证做 `replace(5,12)` 会越界报错，已修复为按长度判断脱敏。**需重新编译并重启后端才会生效**。
- 项目没有独立"支付密码"表，支付校验用的是 `user_info.password`（登录密码，MD5），前台弹窗文案为「账户密码」。
- 拦截器 `OpInterceptor`/`AdminInterceptor` 直接对 `session.getAttribute("role")` 调用 `.equals()`，未登录时理论上会 NPE，但 `SessionInterceptor` 会先拦截，实际不触发。
